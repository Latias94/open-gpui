# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Standalone applications can opt into `open-gpui-log` and `open-gpui-tracing`. Applications install their own logger, tracing subscriber and allocator; native `tracy` and browser `web` instrumentation are explicit Cargo features. SumTree uses the tracing facade without requiring a subscriber.
- Windows background execution uses Win32 thread-pool workers and one-shot timers. The existing foreground queue and dispatch admission API are unchanged.
- `Window::is_resizable`, `Window::is_minimizable` and `Window::has_active_prompt` expose creation options and active window-rendered prompts. A non-resizable window refuses native resize requests. Pending chord timeouts can be paused for a live entity and resume with the remaining duration when it releases the pause or is dropped.
- Breaking with `inspector`: `App::register_inspector_element` takes a renderer factory, created on demand per open Inspector, and `Window::with_inspector_state` returns `Option<R>` when the Inspector has state for the element.

- macOS uses typed AppKit input, window and menu bindings, and optional ScreenCaptureKit now emits the same retained CoreVideo buffer used by the surface element. Capture-enabled binaries that support macOS 12.0–12.2 should weak-link ScreenCaptureKit; capture requires 12.3.
- The obsolete `open-gpui-media` workspace package and handwritten Cocoa bindings are removed. The public capture and surface buffer types are unchanged.

- Wayland deduplicates committed IME cursor rectangles and prefers advertised ext background blur with KDE fallback. `Window::set_client_corner_radii` forwards independent client-drawn corners; the maintained window-shadow example supplies its drawn radii.
- Linux validates shared XKB contexts without local includes for resolved keymaps and splits Wayland/X11 features. X11 `WM_CLASS` writes terminate both fields. Wayland requires `wayland-backend` 0.3.15 and `wayland-protocols` 0.32.10.

- Web text supports the official `CanvasFontFallback` policy: emoji by default, disabled or conservative horizontal CJK fallback. Whole-grapheme Canvas measurement/rasterization uses the existing glyph atlas, selected face properties and post-fallback missing-glyph reports.
- `CosmicTextSystem::font_weight_and_style` reports the selected face. WebPlatform exposes the official backend/fallback constructors, and the platform convenience crate exposes `application_with_web_backend`.
- WebPlatform requests the bundled font's actual `Inter Variable` family, correcting the previous `Inter` request that silently selected a monospace fallback.
- Browser text imports preserve complete UTF-16 scalars and unchanged text inside a replaced selection, including emoji-to-emoji replacement.

- Native window controls include Wayland input regions and layer-shell exclusive-zone/edge updates, macOS simple fullscreen, and the official parent-anchored popup description. Wayland owns native popup positioning, grabs, configure/reposition and dismissal; unsupported backends return `PopupNotSupportedError` for callers choosing in-window fallback.

- Native windows expose opaque state query/restore and user-attention requests. macOS preserves the official workspace/fullscreen restoration policy; Windows requests one flash, X11 preserves and clears urgency hints, and unsupported backends retain no-op behavior. Restoration owns its archive bytes through the existing post-borrow command queue.

- `fs_embed!` reads development assets from the runtime checkout and embeds them in release builds or with `debug-embed`. It exposes the same get/iter and asset trait interface with matching include/exclude filters.

- JSON array union, Markdown source-position fragments, environment-name validation and explicit Unix open-file-limit setup follow the complete official utility APIs. Native command and Windows shell helpers share the low-level core utility owner.

- `open-gpui-path` provides portable Unix/Windows path operations, checked normalized relative paths, local absolute paths, native byte conversion and optional serde. Utility matchers, ordering and file-position parsing consume these canonical path types.

- Path matchers can skip invalid glob patterns with an error callback. Extension sorting and host-independent file-position parsing follow the complete official utility owner.

- HTTP requests support complete-request deadlines, and the native client supports per-read idle timeouts. Redirect overrides use the original client's configuration. Platform TLS initialization falls back to bundled WebPKI roots if loading the platform verifier fails.

- `open-gpui-github-releases` owns release discovery and background-task downloads with digest normalization, status validation and staging. Its fixed official archive parser handles PAX values containing embedded newlines.

- `DedicatedExecutor` reuses a dedicated task session. Dedicated-thread task delivery is nonblocking and preserves cancellation or detachment before the root task arrives. `SharedString` accepts characters and deserializes directly through `SmolStr`.

- Darwin command children share the official `async-process` reaper with `smol`, including adopted PIDs, asynchronous file pipes and owned cleanup on spawn failure.

- Internal drags can lazily offer file payloads to native macOS and Wayland drag sessions. Source-window reentry restores the original typed drag; native callbacks retain an exact session so stale completion cannot end a later drag. Mouse and file-exit listeners use committed element geometry, and drag cursors apply before the next paint.

- Official portable touch gestures synthesize taps, source-aware pans with momentum, long presses and claimed touch drags. Platform gesture tuning, back-gesture vocabulary and Window long-press/prediction controls use the existing input owners. Stateful hover listeners can opt into input-modality-independent tracking without changing visual hover or tooltip policy.

- Input handlers can report their editable element bounds through `element_bounds`, defaulting to `None`; `ElementInputHandler` projects its committed bounds into window coordinates. The Web touch producer preserves contact identity, capture cancellation and tap-only keyboard activation through the existing native input lifecycle.

- `container_query` builds its contents from its allocated size in the same frame. `Anchored::attach` places content against a target corner and flips to the side with more room. SVG elements accept byte data; parsed SVGs can be reused and rasterized at exact dimensions.

- Variable-height lists support measurement readiness, provisional and pending-end anchors, uniform item-height hints/reset, `scroll_to_item` for direct indexed scrolling and explicit pause-following-tail through their existing state owner.

- `GlobalElementId::new` constructs a complete root-first path with its cached hash. Window element stacks retain prefix hashes through deferred drawing and candidate rollback. App borrow conflicts now report attempted and original borrow locations through panics and fallible window updates.

- Web text input uses a textarea mirror with UTF-16 selection, composition, bounded editable context and per-handler `TextInputConfiguration`. `Window` exposes content/selection notifications, virtual-keyboard requests, visual viewport bounds and `WindowInsets`. Configuration and text-session effects publish with accepted frames; native commands execute after the App borrow is released. The mirror retires with its window.
- Breaking: exhaustive matches on `PlatformWindowCommand` and native callback diagnostic operation enums must handle the new text-session variants. Backend implementors that use `PlatformInputHandlerSlot` should delegate `take_input_handler_for_frame` to `take_for_frame`, preserving a checked-out handler during refused redraws. New `InputHandler`, `EntityInputHandler` and optional platform methods have default implementations.

- `open-gpui-apple` owns the shared Apple dispatcher, Metal renderer/atlas, CoreText/OpenType, Keychain and process services. CoreVideo surfaces are available on macOS/iOS; this shared substrate does not add an iOS application backend. macOS window options expose the official opt-in Display P3 color space.

- Windows forwards Restart Manager session shutdown from application windows to the platform quit callback. Completed shutdown flushes logs and exits; asynchronous shutdown retains the official best-effort quit fallback.

- `Application::with_windowing`, `App::request_windowing` and `GraphicalEnvironment` retain an application while a capable native backend switches between headless and graphical operation. Linux exposes explicit allowed `WindowingModes`; application `ActivationPolicy` controls macOS Dock/menu participation separately from each window's activation policy.

- `App::set_window_appearance` overrides macOS native window chrome with any `WindowAppearance`; passing `None` restores system following. Other platforms retain the default no-op through `Platform::set_window_appearance`.

- `ActivityGuard` owns scoped operating-system activity until drop. `App::prevent_idle_sleep` acquires native sleep inhibition; `BackgroundExecutor::prevent_app_nap` separately prevents App Nap throttling on Apple platforms and is a no-op elsewhere. Test contexts expose acquisition counts, delay and error controls.

- `Application::with_restart_arguments` configures owned native arguments for the next restart. The selected executable and each argument reach the existing platform launcher without shell-source interpolation.
- `App::platform_info` reports the runtime host operating system separately from Native/Web delivery. Browser keyboard conventions follow the detected host, including macOS Command bindings, while tests can explicitly select an identity.
- macOS `App::write_credentials_if_not_exists` uses a single Keychain insertion and reports an existing server/account without replacing its secret. The Mac backend exposes reusable typed Keychain operation, cancellation and status errors; the macOS Platform default reports unsupported when a backend lacks atomic insertion.
- `App::read_from_clipboard_async` preserves desktop ready snapshots and supports permission-gated browser text/image reads. Platform-initiated paste forwards the complete `ClipboardItem` through `InputHandler::paste` and `EntityInputHandler::paste`; default handlers insert its text. Web text writing and DOM text/image paste share the existing input-handler lifecycle.
- Seeded randomized element trees and platform tree workloads under `bench-support` preserve official topology, entity-local mutation, cached/hover/animation variants and reproducible workload families. Ordinary benchmark consumers can inspect the accepted rendered Scene without enabling test support.
- `BoxShadow::new` and its blur, spread and inset builders follow the official CSS-order API.
- `ForegroundExecutor::to_send` and scheduler `LocalExecutor::to_send` expose the official Send-only submission handles. Worker submissions keep the captured dispatch destination, scheduler lifetime and foreground accounting; output values need Send, without a Sync requirement.
- Browser Fetch responses stream through the official bounded asynchronous channel, with body-drop cancellation, worker-to-main submission and explicit credential options. Worker startup checks `Atomics.waitAsync` and reports a single-threaded fallback when unavailable.
- System notifications expose application identity, show/dismiss and body/action response APIs across the native backend closure. Unsupported or unavailable delivery remains best-effort; responses use the existing ordered App update owner, with lazy platform initialization and replaceable handlers.
- Official stateful Spring animations support typed and custom targets, velocity-preserving retargeting, pause/stop/cancel/completion, arbitrary phase interpolation and animated parent composition. GPUI and the renderer-neutral motion crate expose the same pure solver types. Element samples and next-frame demand publish with accepted frames.
- With `profiler`, `DebugFrameOverlayMode` and Window controls expose the official hidden/current/detailed draw-time overlay. A rolling 1,000-sample bitmap readout preserves history while hidden and counts completed accepted draws; reset preserves the lifetime count. Direct Scene drawing adds no font/layout dependency or self-refresh timer.
- Browser rendering supports explicit WebGPU or WebGL2 selection and automatic WebGPU-to-WebGL2 fallback with a fresh canvas. Packed WebGL data preserves the shared renderer's clip ancestry, local transforms and complete-frame refusal. The browser smoke gate exercises real screenshots, resizing and public input/docking consumers.
- `Scene` supports complete owned drawing-data copies, including clip arenas and paint journals. Copies preserve their original geometry-validity associations without transferring atlas leases or presentation authority.
- Optional native debug hot reload follows the official GPUI/Subsecond 0.7.10 mechanism: build/process-matched patches, foreground application, window refresh, and typed, stateless and stored erased View render boundaries. Run with `dx serve --hot-patch`; compatible render-body edits preserve existing model state. Release/WebAssembly transport exclusion, failed loads, required restarts and disconnects remain explicit. The independently locked native consumer provides an actual edit/build/apply and Submitted-scene pixel acceptance procedure, including the required upstream dx x64 jump-stub backport for the qualified Windows tool.

### Breaking Changes and Migration Notes

- Full `WebPlatformOptions` literals must provide `canvas_font_fallback` or use `..Default::default()`. Select `CanvasFontFallback::Disabled` to retain loaded-font-only rendering.

- Handle `WindowKind::AnchoredPopup(PopupOptions)` and the hidden `PlatformWindowCommand::ToggleSimpleFullscreen` / `NativePlatformCommandKind::ToggleSimpleFullscreen` in exhaustive matches. An anchored popup names one live parent in the opening App through `PopupOptions::parent`; do not also set `WindowOptions::transient_for`. Its window-bounds origin is ignored. Non-grabbing popups always use a nonactivating first appearance, including when the generic focus field keeps its default; explicit grabs retain their native focus policy. Simple fullscreen is a native presentation action through the post-borrow command queue and preserves normal restore bounds; it does not create a typed placement ticket.

- Custom backends use the optional `PlatformWindow::on_close_required` callback for irreversible dismissal before native destruction. It bypasses a user close veto while preserving presentation shutdown and native retirement. Keep `on_close` for the true native terminal. Hidden callback diagnostics add `NativeCallbackKind::CloseRequired`.

- The hidden backend integration enum `PlatformWindowCommand` is `Clone` rather than `Copy` and adds `RestoreNativeWindowState(Arc<[u8]>)`; `requires_interaction_authority` now borrows it. Clone when retaining a command across dispatch and update exhaustive matches, including `NativePlatformCommandKind::RestoreNativeWindowState`. Unsupported dispatchers should return `Unsupported`; ordinary `PlatformWindow` implementors inherit the default no-op services.

- `merge_json_value_into` replaces colliding arrays instead of appending them. Use `union_json_value_into` for deduplicating array composition. Native shell/process modules are unavailable on wasm; the unused `take_until` utility reexport is removed.

- On Windows, use the canonical `open_gpui_util::get_powershell()` or `open_gpui_core_util::get_powershell()` returning `Option<String>` instead of the old shell-module `Option<PathBuf>` API. Convert to `PathBuf` where a native consumer requires it. `get_windows_bash` is Windows-only.

- Import canonical relative path types and their conversion trait from `open_gpui_path::{rel_path, PathExt}`; `open_gpui_util` also provides the official ergonomic reexports of those same types. `PathStyle::Posix` becomes `Unix`, and its join/prefix APIs follow the portable package's checked component semantics. Use `RelPath::from_unix_str` for already-normalized input. The utility `normalize_path` function moves from the root to `open_gpui_util::paths`; no old root alias remains. Handle `SortOrder::Extension` in exhaustive matches.

- GitHub APIs move out of `open_gpui_http_client::{github, github_download}` into `open_gpui_github_releases`. Pass a `BackgroundExecutor` to `download_server_binary` / `download_server_raw_binary` and await their returned `Task`. The lower HTTP package no longer reexports `anyhow` helpers or owns native archive/download dependencies.

- The native HTTP implementation selects official `zed-reqwest` revision `33bc764aa15ff7b200bf7c93bd96e24878d53e14`. Direct consumers passing reqwest clients must select that same package/source. The former registry-client reconstruction cache is removed; request-local redirects preserve imported client configuration. Custom `HttpRequestExt` implementations must provide `timeout`.

- Native blocking executor APIs, scoped background futures and the `block_on` reexport are unavailable on WebAssembly. Web quit observers run asynchronously as best-effort cleanup; native shutdown retains its bounded wait. Enable `open-gpui/wasm-threads` for dedicated Web workers with a shared-memory build; the Web backend forwards it from `multithreaded`.

- Darwin command `Child` pipes now use `smol::Async<File>` instead of `Unblock<File>`. Consumer workspace roots must select `async-process` revision `0b6d6713570af61806e1e5cb40e0f757cb93fd9d` through `[patch.crates-io]`, as shown in the independent consumer. Cargo does not inherit a dependency's root patches; the direct Darwin dependency and `smol` must resolve to that same package.

- `PlatformInput::ScrollWheel` becomes `PlatformInput::Scroll`; use `ScrollEvent` and initialize its `source` field in complete literals. The official deprecated `ScrollWheelEvent` type alias remains available. Handle `TouchPhase::Cancelled` and the new touch/long-press/drag/back-gesture variants in exhaustive matches.

- `Window::paint_image` now takes both the element bounds and the image layout bounds. Pass the same bounds twice for an uncropped low-level image. Handle `SvgSize::ExactSize` in exhaustive matches.

- `GlobalElementId` dereferences to an immutable `[ElementId]`; mutable path dereferencing is removed so cached hashes remain valid. Use `GlobalElementId::new` to construct paths and `accesskit_node_id` for semantic node identity. The hidden `AppCell::try_borrow_mut` returns the framework Result with borrow-origin diagnostics rather than `std::cell::BorrowMutError`. `AssetLogger` now requires Debug errors and logs their complete diagnostic representation.

- Import shared Apple services from `open_gpui_apple`, including `AppleTextSystem` and `keychain`; macOS retains application/window/input APIs. `WindowOptions` adds `use_display_p3` (default `false`), so explicit complete literals need the new field. Metal shaders follow the fixed target's macOS 12 deployment floor and target-specific iOS SDK selection.

- Native Windows graphical initialization occurs before the launch callback rather than at platform construction. `WindowsPlatform::new(false)` starts without a GPU; enter the launch callback or complete `Platform::request_windowing` before opening graphical windows. Fixed-headless constructors remain unable to attach later. Windowing changes require complete window and native-resource retirement. Deferred platform implementations preserve the caller's validation through physical connection replacement.

- Custom `Platform` implementations must provide `prevent_idle_sleep(&str) -> Task<Result<ActivityGuard>>`. Await the acquisition and retain its guard for the operation; dropping an unpolled ready acquisition also releases its activity. Unsupported implementations should return an explicit error. `PlatformDispatcher::prevent_app_nap` has a default no-op.

- `Platform::on_quit` now takes `Box<dyn FnMut() -> bool>`. Return `true` only when shutdown completed synchronously; queued work and pending native retirement return `false`. Windows keeps its ordinary quit loop alive until `quit_after_terminal_shutdown` acknowledges completion. Forced OS session shutdown may allow only best-effort progress before termination.

- Custom `Platform` implementations must provide `platform_info`, reporting the host OS separately from Native/Web delivery. `Keystroke::parse` and `KeyBinding::new` take static strings with explicit modifiers. Load dynamic or `secondary-` bindings with `Keystroke::parse_with_os` or `KeyBinding::load(..., &App)`, which uses the application's actual keyboard mapper and host OS. Format or serialize strokes with `.display(os)` / `.unparse(os)`; direct stroke `Display` is removed. Secondary modifier helpers, default key contexts and window shortcut labels now receive App/OS facts. Command binding projection/loading, shortcut diagnostics and capture APIs propagate those same facts.
- DevTools command keybinding probes take a fallible callback returning an App-prepared `SnapshotProbeSnapshot`. Publish owned facts after projecting on the App thread. The payload field `installed_key_binding_count` becomes `key_binding_count`, since a projection does not establish installation.
- Native input diagnostics add `NativeInputHandlerOperation::Paste`; update exhaustive matches. Custom `Platform` implementations inherit a ready asynchronous clipboard read. Web text controls should leave the browser paste shortcut unconsumed and handle DOM paste, while explicit menu actions can await the asynchronous read; binding both paths would duplicate insertion.
- The test-support `proptest` reexport now uses official 1.12, and `property_test` passes its reexport path using that version's supported syntax. Consumers mixing the property prelude with their own rand dependency should import the trait from their own RNG version explicitly.
- Construct `FetchHttpClient` with the originating `ForegroundExecutor::to_send()` handle; the executor-free constructors, `Default` and unsafe single-thread assumptions are removed. `with_user_agent` also takes that handle. Explicitly install the client on the Application before startup; platform factories expose the same construction. GPUI dispatch-facing async-task types use the fixed source `015845a19fc31752c02367567d3b8900a406f9da`; consumers implementing the lower-level scheduler contract must select that source when naming its task types directly.
- Native callback diagnostics add `NativeCallbackKind::SystemNotificationResponse`; update exhaustive matches over this test/integration enum. Ordinary Platform implementors inherit the default notification no-op methods.
- Replace `MotionSpringPhysics` with `MotionSpringOptions::new(SpringConfig::new(stiffness, damping, mass))`; the former constructor ordered mass first. Use `with_epsilon` for positional tolerance and the official natural-frequency velocity threshold. Advanced specs use `from_options` / `options`. Review-duration and reported-bounce hints move to `MotionSpringPolicyHints`; they do not change physical sampling. Domain freeze-at-cancel remains distinct from official `SpringPlayback::Cancelled`, which restores the original initial value.
- `Animation` adds public `synced` and `max_fps` fields. Prefer `Animation::new` with `repeat_synced` / `with_max_fps` builders, or initialize the added fields in explicit struct literals. Easing outputs may now overshoot the unit interval if they remain finite.
- The maintained workspace requires Rust 1.93 for the official upstream WGPU/Naga revision `cddb2f5d80dc0009b2ef6767635140cacf90a007`, including Vulkan surface teardown and WebGL reconfiguration corrections. Applications passing WGPU types to `open-gpui-wgpu` must select that same source revision; a registry version with the same package version has a different Rust type identity. Earlier Rust 1.92 qualification remains tied to its recorded revisions.
- Native `WgpuContext` constructors now take the intended `WgpuSurfaceConfig`, allowing adapter selection to configure a new surface once. Browser constructors take the prepared canvas and return `PreparedWebGraphics` with its matching surface; pass it to `WgpuRenderer::new_from_surface`. `WebGpuContextOptions` and `WebPlatformOptions` add `backend_preference`; use `WebBackendPreference::Auto`, `WebGpu` or `WebGl`. Forced selections do not try another backend. The current Web platform owns one normal top-level window, refuses additional/popup/floating/dialog windows, and does not support reopening it after close.
- `PlatformAtlas::get_or_insert_with` and its diagnostic variant now consume `AtlasKey`; clone explicitly when the caller retains a key. Custom backends can reuse the official `AtlasState`/`AtlasBackend` key owner. Builders run while the atlas is locked and must not re-enter it. Test and Linux headless windows share `HeadlessAtlas`, preserving exact texture-instance leases and diagnostics. `contains` is available with test or benchmark support.
- `test-support` no longer enables entity-handle leak tracking. Select `leak-detection` or set a nonempty `GPUI_LEAK_DETECTION` when building tests that require tracked snapshots; `0` is nonempty too. Without tracking, snapshots are no-ops while weak release assertions still check live handles and pending cleanup. Use `App::is_test`, `AsyncApp::is_test` and executor queries to identify deterministic execution; compiling test support preserves normal home-directory and native runtime behavior.
- Benchmark contexts now require `bench-support` independently of `test-support`. Replace the old virtual `BenchAppContext::new(name)` / `with_seed` and two-argument `#[open_gpui::bench]` functions with the official context-only signature, optional input and by-value `StdRng`. Use `cx.bench_iter` / `cx.bench_task`, Criterion 0.8.2 and `Criterion<BenchMeasurement>`; the maintained Canvas and independent benchmark consumers demonstrate the migration. Headless renderer factories now return `Result<Option<_>>`, and `PlatformHeadlessRenderer` requires a no-readback `render_scene` method.
- Replace the fork's `Window::is_accessibility_active` with the official `Window::is_a11y_active`; no alias remains. Use `Window::is_a11y_enabled` for configuration checks independent of assistive-technology attachment.
- `View` and `ViewElement<V>` now supply the common embedding path for entity-backed views and stateless components. `Component<C>` and the direct `Element` implementation on `AnyView` are removed. Migrate `Component::new(value)` to `ViewElement::new(value)`, and direct handle `into_any()` calls to `into_any_element()`. `Entity::cached` and `AnyView::cached` return their typed `ViewElement`; convert conditional element branches with `into_any_element()`. `IntoElement` derives support manual `View` implementations as well as `RenderOnce`.
- `WindowOptions` adds independently configurable inactive, low-power and thermal frame intervals. Complete struct literals must supply them or use `..Default::default()`. Exhaustive `FrameSkipReason` consumers must handle `LowPowerFrameRateLimit`; ordinary dirty and pending-presentation work now follows the same applicable limits as animations.
- Profiler `FrameTiming` now carries the captured frame signal, display refresh interval and draw phases; frame-duration snapshots include per-refresh statistics. Exhaustive foreground-event consumers must handle view-phase timing, and journal-entry consumers must handle raw input-activity state. Measurement version 3 replaces `HangTrigger::Budget` with the distinct `LateFrame` and `BlockingWork` rules and includes active-use attribution in serialized incidents.
- Custom `PlatformWindow` implementations use `schedule_frame` for pending work; the completion-driven `completed_frame` hook is removed. Demand-driven backends also supply a weak `frame_waker` that uses their existing callback path safely while App is borrowed. Native callback maintenance remains separate from frame scheduling.
- `RequestFrameOptions` now carries `signal_at` and `signal_source`. Custom backends must preserve the earliest captured timestamp and its matching `FrameRequestSource` when coalescing callbacks; use `None` when the timestamp is unavailable. `PlatformFrameSignal` provides the official shared accumulator and feature-gated capture. Exhaustive foreground journal and interval-boundary consumers must handle platform signals, reentrant deferrals and completed frame skips.
- Custom `PlatformDispatcher` implementations must return admission from `dispatch_on_main_thread` and `dispatch_on_main_thread_when_idle`: return `true` after accepting the runnable, and `false` only after refusing it with correct local-future thread ownership. Scheduler accounting settles synchronous refusal; a later asynchronous foreground rejection must settle its admitted count on the originating thread. A failed native wake after successful queue insertion remains admitted.
- Register wake handlers through `App::on_system_wake` and retain its returned `Subscription`; `Application::on_system_wake` is removed. Multiple wake and new `App::on_system_sleep` subscriptions coexist. Custom backends must implement `Platform::on_system_sleep`, `PlatformWindow::visibility` and `PlatformWindow::on_visibility_change` with the documented native signal semantics.
- Enable `profiler` to collect task/action statistics and Window input/draw/presentation measurements. The former `input-latency-histogram` feature is removed; migrate explicit consumer selections to `profiler`. Builds without it retain callable empty task/action accessors without creating timing buffers.
- Custom platforms must implement `Platform::on_displays_changed`, `PlatformDisplay::refresh_interval` and `PlatformWindow::on_display_changed`. Deliver display hints after publishing platform state; return `None` for an unavailable refresh interval. Linux headless now reports no displays rather than a synthetic monitor. `bitflags` is now a required core dependency, matching the shared public display types; remove the retired optional `bitflags` feature from consumer selections.
- `App::fetch_asset` now returns `Option<A::Output>` instead of a shared task and first-load flag. Results become visible after foreground publication. `ImageLoadingTask` and `ImageCacheItem::{Loading, Loaded}` are removed; custom image caches construct an owning `ImageCacheItem::new`, call `use_image` for each interested view, and use `get` for non-subscribing inspection. Dropping a pending entry cancels its load; loaded images still require the cache's existing window disposal.
- Raster decoder failures from `ImageAssetLoader` now use `ImageCacheError::Other` through the shared decoder's contextual error, following the upstream implementation. Consumers matching error categories should inspect the contextual decoder error rather than requiring `ImageCacheError::Image`.
- `TemplateColumnMinSize` is renamed to `GridTemplateMinSize` without an alias; custom style/schema consumers must update the type name. Window and prompt roots fill their auto dimensions from the viewport; set explicit dimensions when shrink-wrapped root sizing is required. Stack growth is now opt-in through the `stacker` feature. The framework uses Taffy 0.15 and its updated alignment/measurement contract.
- `Window::text_system` now returns `&Rc<WindowTextSystem>`. Keep window layout/cache access on its owning thread and use the shared `Arc<TextSystem>` for background font work. The unused `shape_line_by_hash`, `try_layout_line_by_hash` and `layout_line_by_hash` interfaces are removed; materialize source text and use the ordinary `shape_line` / `layout_line` APIs.
- `ShapedLine::split_at` explicitly rejects adjusted source lengths and invalid UTF-8 boundaries. Raw `LineLayout::split_at` requires a caller-validated source boundary. Both preserve shaped glyphs and original visual geometry; fragments are not independently reflowed bidi text.
- `LineWrapper::wrap_line` now takes an explicit third `IndentAdjustment` argument. Pass `IndentAdjustment::default()` for matching indentation, or select `NoIndent` / `ExtraColumns(n)`. Exhaustive matches must also handle `TruncateFrom::Middle` and `TextOverflow::TruncateMiddle`.
- Renderer-record fields `PolychromeSprite::grayscale` and `Underline::wavy` now use `PaddedBool32`: construct them with bool `.into()` values. Author-facing style and paint APIs still accept bool; custom GPU consumers read a fully initialized four-byte unsigned value.
- `ArenaClearNeeded::clear` now requires the same `&mut App` used by `Window::draw`: migrate `window.draw(cx).clear()` to `window.draw(cx).clear(cx)`. Nested draws defer cleanup until the enclosing draw ends, and clear tokens reject another App.
- Windows command dispatchers must handle `PlatformWindowCommand::CompleteNativeFrame`. The native backend uses the existing post-borrow command queue for DirectManipulation and IME maintenance after a retained frame request; unsupported custom backends must report that outcome.
- The UI framework authority-convergence changes are intentionally alias-free. Use the [Open GPUI v0.3 UI migration guide](docs/ui/migration-v0.3.md) for complete before/after examples and ownership rules.
- `open-gpui-form` now uses store-bound validation and submission tickets: `FormStore` is no longer `Clone`, async completion and submit completion return typed outcomes, ticketless finish APIs are removed, and active validation participates in derived form status and submission eligibility.
- `open-gpui` pointer capture is now explicitly window- and owner-scoped: retain and bind a `PointerCaptureHandle`, pass the initiating button to `Window::capture_pointer`, release through the same handle, use the routed-event-target query separately from physical hover, and replace `Window::remove_window()` with `Window::remove_window(cx)`.
- `open-gpui` makes renderer texture leasing a required `PlatformAtlas` contract. Third-party backends must implement `atlas_texture_lease_epoch`, atomic `acquire_atlas_texture_leases`, and matching `release_atlas_texture_leases` with exact `AtlasTextureInstanceId` generations; `AtlasTile` literals and host/shader ABI mirrors must add `texture_generation` plus zero `texture_generation_padding`. The former `Unsupported` defaults are removed because they compiled successfully while silently dropping retained glyph, icon, emoji, and image sprites.
- `open-gpui` adds `PlatformWindowHit::{ProvisionalPassThrough, NoInputPassThrough}` for exact-generation native routing through gated provisional and pointer-transparent windows. - WGPU encodes each frame using the acquired surface texture size and omits the path composite when its batch did not rasterize. Metal uploads the frame's surface geometry together, while each video surface retains and binds its own two planes.

- Ordinary `App::open_window` preserves downcasts to backend errors such as `PopupNotSupportedError`, allowing callers to choose a fallback. `open_window_detailed` retains its typed synchronous failure stage.

- Windows file and message dialogs run on dedicated STA threads, serialize per native owner and cancel when their caller or owner closes. Native retirement waits for active dialog work without blocking the foreground executor. File-picker failures are reported separately from user cancellation.
- Windows keyboard accelerators route directly to registered GPUI windows without sending private messages to foreign hosts. Stationary no-button mouse moves avoid duplicate input while retaining hover reentry, held-button and physical-geometry changes; private messages retain validation and native-generation checks.
- Windows composition fallback checks that the optional system function exists before calling it.

- DirectX ordinary/path-sprite and WGPU path-sprite alpha now use standard source-over composition. Windows DirectComposition content stays below native child windows, including renderer reconstruction; child HWNDs consequently remain above GPUI-drawn overlays.

- Scroll clamping snaps recomputed padding to the same device-pixel grid as layout, avoiding phantom sub-pixel scroll ranges. Touch timer and lifecycle integration use the existing executor clock, input transactions and Window retirement boundaries.

- Image object-fit preserves explicit aspect ratios and crops Cover content before applying visible-box rounded corners. SVG rasterization caps both dimensions at the official 8192px limit.

- Uniform lists retain accurate visible rows and local item spacing at large scroll offsets by applying the official f64 range and local-position calculation. Error logging preserves chained diagnostics, backtraces and caller locations through a shared non-generic sink.

- Window closure retains its native owner when presentation-shutdown preparation panics, retries through the existing retirement queue and keeps windowing changes blocked until exact native completion. Linux mode changes also discard stale Wayland drag reads, release queued foreground captures and stop owned timers without canceling a standalone executor returned before application launch.

- Debug source labels respond to the host's secondary modifier even with sibling keyboard focus, update their underline when the pointer crosses the displayed text bounds, and preserve ordinary clicks when the modifier is absent.
- Windows credential reads, writes and deletion run on the existing background executor. Reads accept null account/blob fields and free native storage before propagating conversion errors. Linux uses the fixed upstream oo7 prompt-stream correction so a stream ending before Completed returns an I/O error instead of panicking.
- Windows clipboard writes replace embedded NULs with spaces before encoding and hashing, preserving the complete normalized text and its metadata. macOS pasteboards and custom type strings retain their Objective-C ownership, and reads return Rust-owned bytes beyond autorelease-pool lifetimes.
- Native ingress avoids redundant foreground wakes while an App borrow or active post-borrow convergence already owns delivery. Pure animation no longer keeps benchmark idle draining alive. Refused visibility candidates preserve the accepted Div mouse press until an admitted frame removes its interaction membership.

## [0.2.0] - 2026-07-07

Open GPUI v0.2.0 is the first broad foundation release for the fork. It publishes the component, docking, canvas, command, motion, web, and platform crates to crates.io under the Open GPUI package names.

### Highlights

- Component library foundations are now available through `open-gpui-ui-core` and `open-gpui-ui-components`, including theme tokens, accessibility helpers, overlays, choice/menu/select/combobox primitives, table/tree foundations, and conformance coverage.
- `VirtualizedList` is now a real component-library primitive instead of a text-label list: it supports stable keys, typed rows, custom row rendering, selection modes, sections, sticky metadata, typeahead, measured rows, and motion-backed active-item chrome.
- `open-gpui-command` adds command-center building blocks for providers, keymap preflight, shortcut inspection, conflict diagnostics, palette history, and provider refresh flows.
- `open-gpui-docking` adds a GPUI-native docking foundation with tab stacks, split layouts, drag/drop targets, floating panels, multi-viewport routing, lifecycle helpers, debug status, and a native example.
- `open-gpui-canvas` adds a reusable infinite-canvas foundation with JSON Canvas import/export, journaling, tool sessions, runtime caches, persistence hooks, and native examples.
- `open-gpui-motion` adds renderer-neutral motion primitives for deterministic timeline/spring sampling, progress runs, keyed sequences, policy validation, frame demand, geometry, and layout projection.
- Web and wasm support is substantially more usable: default fonts are bundled, canvas sizing is initialized correctly, callbacks avoid borrow panics, and the browser `hello_web` path is runnable.
- Dependency baselines were refreshed across the workspace, including `windows` 0.62, `wgpu` 29, `reqwest` 0.13, `wasm-bindgen` 0.2.126, and related platform bindings.

### Fixes

- Fixed Windows dispatcher and DirectWrite integration after the `windows` 0.62 upgrade.
- Fixed Linux Wayland clipboard/headless behavior and X11/headless regressions.
- Fixed native text rendering in examples, streamed `reqwest` body reads, SVG renderer regressions, list scrolling behavior, scheduler leak checks, and Darwin process-tree cleanup.
- Fixed focus restore behavior for Select, Combobox, and dialog Command overlays after selection, Escape dismissal, and outside-press dismissal.
- Fixed package archives so publishable crates include Apache-2.0 license text and NOTICE attribution files.

### Security

- Resolved the cargo audit findings tracked during the dependency upgrade sweep.

### Breaking Changes and Migration Notes

- Public-facing defaults now use Open GPUI naming. `ZED_ALLOW_ROOT` becomes `OPEN_GPUI_ALLOW_ROOT`, `get_shell_safe_zed_path` becomes `get_shell_safe_app_path`, and `get_zed_cli_path` becomes `get_open_gpui_cli_path`.
- Platform-specific identifiers for keyrings, pasteboard metadata, Windows credential targets, and Windows window classes now use Open GPUI names.
- `open-gpui-http-client` no longer exposes Zed Cloud/API/LLM URL helpers such as `build_zed_api_url`, `build_zed_cloud_url`, and `build_zed_llm_url`.
